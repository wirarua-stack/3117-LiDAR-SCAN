Measurement records: Save measurement stores a label, stable measurement ID, creation time and A/B local-world coordinates in project metadata. Distance is derived from endpoints, not stored separately. Saved measurements can be recalled onto the model and are preserved when duplicating projects. Missing measurement fields in older projects/drafts decode as an empty list. A repeated save of the same record ID is idempotent; separate user saves create separate records. Rename/delete of saved measurements is not implemented yet.

Measurement CSV reports include project/measurement IDs, labels, UTC measurement time, metres, A/B coordinates, straight-line distance, coordinate reference, method and non-survey-validated status. Reports use UTF-8 BOM, quoted text/escaped quotes, CRLF records, and apostrophe-prefix mitigation for formula-like text labels. Reports are immutable snapshots and recorded in export history. Export is off-main; adding measurement metadata remains atomic on the main actor. Geometry exports still exclude measurement annotations. Device UI/report import acceptance remains pending.

Stability update: retained capture geometry is capped at 500,000 vertices, 1,000,000 triangles and 2,000 anchors. Anchor updates account for replacement sizes before copying buffers. Reaching the cap or receiving a memory warning pauses capture and requires saving/starting another scan. This is not a guarantee of bounded total process memory: ARKit, GPU, scene rendering and archive buffers need device profiling.

Capture explicitly uses the main delegate queue and copies accepted mesh buffers synchronously, without spawning unbounded mesh-copy tasks. Paused captures ignore geometry updates/removals. Background/inactive transitions, interruptions and serious/critical thermal states pause capture; resumption is manual. Failed sessions cannot resume and mix coordinate frames. Closing a capture prevents a delayed camera-permission response from restarting it. Measurements require normal tracking.

UI save/load/export/duplicate paths now perform archive I/O and encoding/decoding in detached tasks. A shared operation indicator prevents overlapping mutations and clears after failure. Metadata commits and initial metadata reads remain synchronous on the main actor. SceneKit object assembly yields between anchors; file-operation progress is indeterminate, not a measured percentage.

Recovery update: each capture has a stable UUID and an atomic, versioned draft envelope containing its project provenance and mesh snapshot. Capture attempts a checkpoint approximately every 20 seconds (plus write time) and on becoming inactive. Busy operations skip checkpoints. The capture screen displays the last successful completion time or failure. The dashboard discovers draft filenames without decoding geometry and offers recovery into a saved model or explicit confirmed discard. Recovery validates format/identity/geometry, preserves capture date and ID, and does not resume an AR session. A committed project is never overwritten by recovering a stale draft of the same ID. Drafts are removed only after project metadata is committed, or explicit discard; corrupt drafts remain available rather than being silently deleted.

Recovery limits: suspension or termination can interrupt a checkpoint, so only the last successfully written draft is recoverable. There is no guarantee of a final background write or a maximum 20-second loss window. Before the first checkpoint there is no recovery. Atomic replacement preserves the prior completed file during ordinary interrupted writes, but does not guarantee recovery from storage corruption or device loss. Full JSON checkpoints add temporary memory and disk usage; hardware profiling and storage-failure testing remain necessary.

Implementation references: Apple's [ARSession delegate queue](https://developer.apple.com/documentation/arkit/arsession/delegatequeue) and [thermal notifications](https://developer.apple.com/documentation/foundation/processinfo/thermalstatedidchangenotification). Automated tests cover budget boundaries and background file-operation round trips/failure cleanup; physical lifecycle, thermal, memory and relocalization acceptance is still outstanding.

New source update: export selector supports OBJ mesh and ASCII PLY/XYZ point clouds derived from reconstructed mesh vertices. Coordinates are transformed into the local capture frame in metres (Y up), not georeferenced. Vertices are not deduplicated or uniformly sampled and contain no RGB, intensity or raw depth. PLY embeds this provenance in its header; XYZ is numeric XYZ rows only. This is not raw LiDAR capture or point-cloud fusion. Export history retains the selected format. The viewer resets stale geometry, share URLs and measurement state when switching projects. Unsaved scans require discard confirmation, including protection against swipe dismissal.
